# TypeScript Data Modeling

For each answer, separate compile-time guarantees from runtime guarantees.

1. What is the difference between a domain entity and an API DTO?
2. When should a field be optional, nullable, or required with an explicit empty value?
3. How does a discriminated union improve the safety of processing success, failure, and skipped outcomes?
4. Why do TypeScript types not replace runtime validation at an HTTP boundary?
5. When would you choose a `Map` over an array for a collection of entities?
6. What are the tradeoffs between normalized data and nested data in a client application?
7. How would you model an identifier so that a movie ID cannot accidentally be passed where a user ID is expected?
8. What invariants belong in a constructor or factory instead of being left to callers?
9. How would you model partial updates without making every field ambiguous?
10. What does a good result type for expected domain failures look like, and when should an exception still be used?
