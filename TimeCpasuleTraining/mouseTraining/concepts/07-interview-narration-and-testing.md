# Interview Narration And Testing

Practice saying the answer while coding, not only after the solution is complete.

1. What questions should you ask before implementing an ambiguous requirement?
2. How do you state the simplest viable model before writing code?
3. What happy-path example would you use to manually verify a queue processor?
4. Which edge cases should be tested first for a calculator, and why?
5. How do you communicate that a choice is intentionally scoped to the exercise?
6. What is the difference between a unit test, a component test, and an integration test for the watchlist feature?
7. How would you discuss a performance optimization you are deliberately not making yet?
8. How do you recover in the interview if your first implementation exposes a flawed assumption?
